Passing a function into a function

function repeat(n, action) { for (let i = 0; i < n; i++) { action(i) // repeat calls it, not you } } repeat(3, (i) => console.log("Hi", i))
inside repeat

A function passed in as an argument is a callback — you hand it over, somebody else decides when to call it. A function that takes one, like repeat, is a higher-order function. Every array method later today works exactly this way.

JavaScript · Workshop 08Functions as values
[ ARRAY METHODS ]
09

Methods that take a callback

forEach
Run a function for each element. Returns undefined.
map
Transform every element → a new array, same length.
filter
Keep the elements where the test returns true.
find
The first element that matches, or undefined.
some
true if at least one element matches.
every
true if all elements match.
findIndex
The index of the first match, or -1.
reduce
Combine everything into one value.

Every one of them takes a function. Your function is called once per element, one at a time — exactly like the filter we just built. You never write the loop.

const products = [ { name: "Milk", price: 2.5 }, { name: "Bread", price: 1.2 }, { name: "Cheese", price: 6.8 } ] console.log(products.filter(p => p.price < 3)) console.log(products.find(p => p.name === "Cheese"))

filter always gives you an array — possibly empty. find gives you one element, or undefined if nothing matched. Mixing those two up is the classic bug in the class work.

Read it as: "start at 0, and for each element update the running result". Whatever the callback returns becomes the sum of the next call — forget to return and everything falls apart.

const numbers = [4, 8, 15, 16] const max = numbers.reduce( (best, n) => Math.max(best, n), // keep the larger one numbers[0] // start from the first ) console.log(max) // 16 const sum = numbers.reduce((s, n) => s + n, 0) const average = sum / numbers.length console.log(average) // 10.75

Always pass a starting value — 0 for a sum, [] to build an array, {} to build an object, the first element for a max. The running result can be any type you like.

17

Which method do I need?

a new array, same length, changed items→maptransform
a smaller array, only the matching items→filterkeep
one item→findfirst match
a yes/no answer→some / everyat least one / all
one value out of many (sum, max, count)→reducecombine
just do something with each item→forEachno result
// filter returns an array — so another method can follow straight after it const cheap = products.filter(p => p.price < 3).map(p => p.name) console.log(cheap) // [ 'Milk', 'Bread' ]

Chaining works because each method returns a value. filter hands back an array, so map can start on it. But find hands back one element — nothing to chain a map onto.

Pick the method

30 seconds with your neighbour: which method fits each one?

Add 18% VAT to every price→mapsame length, every item changed
Only the songs longer than 3 minutes→filtera shorter array
The student whose id is 7→findone element
The total price of the shopping cart→reduceone value
Is at least one product out of stock?→sometrue / false

Stuck? Ask what should come OUT. A same-length array means map. A shorter array means filter. One element means find, one value means reduce, and true/false means some or every.
