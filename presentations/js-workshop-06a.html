Functions in 60 seconds

Parameters vs arguments
  • function add(a, b) — a and b are the parameters, the names
  • add(2, 3) — 2 and 3 are the arguments, the real values
Return
  • return sends a value back to where the call was written
  • it also ends the function — nothing after it runs
function add(a, b) { return a + b } console.log(add(2, 3)) // 5 function f(x) { console.log(x + 2) } // prints, but never returns console.log(f(1)) // 3, then undefined

The one that catches everybody: printing is not returning. f(1) prints 3 by itself, but the call has no value to give back — so console.log(f(1)) prints undefined right after it.

Scope in 60 seconds

outside every function→global — visible everywhere
inside a function→local — gone when the call ends
inside a { } block→block — gone when the block ends
same name, both levels→the inner one winsshadowing
let x = 2 if (true) { let x = 4 // a different x — block only let y = 7 console.log(x) // 4 } console.log(x) // 2 — the outer x was never touched console.log(y) // ReferenceError: y is not defined

This is localBlockScope.js from class. y only ever existed inside the block — outside it, nobody has heard of it. A parameter is a local variable too, so it shadows a global of the same name.

When a function reaches outside

let counter = 0 // lives outside the function function makeKhinkali() { console.log("rolling") // reaches outside: prints counter++ // reaches outside: changes counter return counter // gives a value back } const plate = [makeKhinkali(), makeKhinkali()] console.log(plate, counter)

A side effect is anything a function does besides returning a value — printing, changing an outer variable, pushing into an outer array. This is the khinkali.js counter from class, and it is not a bug. It is just something to do on purpose, knowing you did it.

06

Change it, or return a new one

Pure — no side effects
  • same input → same output, every single time
  • touches nothing outside itself
Not pure
  • changes something outside: console.log, push on an outer array
  • depends on something outside: Math.random, the clock
function addItem(list, item) { list.push(item) // changes that array } function withItem(list, item) { return [...list, item] // copies, then adds } const cart = ["Milk"] addItem(cart, "Bread") const bigger = withItem(cart, "Eggs") console.log(cart, bigger)

Prefer returning a new value. A pure function is easy to test and impossible to break from a distance. Impure is fine when you mean it — printing is impure, and printing is useful.

Default parameters

function greet(name = "stranger") { return `Hello, ${name}!` } console.log(greet()) console.log(greet("Nino")) console.log(greet(undefined)) function power(base, exponent = 2) { return base ** exponent } console.log(power(5)) console.log(power(2, 10))

A default is used only when the argument is missing — that is, when it is undefined. Any other value, even 0 or an empty string, is used exactly as you passed it.

08

Three quick ones

  • 01What does console.log(f(1)) print if f has no return?Whatever f prints by itself, and then undefined — the call had no value to give back.
  • 02Is (a, b) => a + b pure? Is n => console.log(n) pure?Yes — it only returns a value. No — printing reaches outside the function.
  • 03Given function f(a = 1), what is a during the call f(0)?0, not 1. Only a missing argument triggers the default, and 0 is a real value.

If any of these surprised you, that is exactly the slide to go back to — say so now rather than in the homework.

09

Part 1 takeaways

  • 01A variable lives where it is declared — global, or local to a function or a block. Inner wins.
  • 02Returning is quiet. Anything else a function does — printing, changing an outer variable — is a side effect.
  • 03A pure function gives the same answer for the same input and touches nothing outside. Prefer returning new values.
  • 04A default parameter fills in only when the argument is missing.
