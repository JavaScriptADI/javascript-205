Parameters are the names in the definition; arguments are the real values you pass in the call. return gives the result back to the place where you called the function. No return? That place receives undefined.

Return ends the function

function isAdult(age) { if (age >= 18) { return true console.log("never runs") // unreachable } return false } console.log(isAdult(20)) // true console.log(isAdult(15)) // false

Several returns are fine — the first one reached wins, and nothing after it runs. That is why an early return is a clean way to handle a special case.

let x = 1 if (true) { let x = 2 // new x, block only console.log(x) // 2 } console.log(x) // 1 let city = "Tbilisi" function visit(city) { // shadows city console.log(city) // Batumi } visit("Batumi") console.log(city) // Tbilisi

A block is the { } code block of an if, a for or a function. Inner wins inside its block — the outer variable is untouched. A parameter is a local variable too, so it shadows a global with the same name.

Pure functions and side effects

Pure
  • same input → same output, every time
  • touches nothing outside itself
Not pure
  • changes something outside: console.log, push on an outer array
  • depends on something outside: prompt, Math.random
function addItem(list, item) { list.push(item) // changes the array } function withItem(list, item) { return [...list, item] // copies, then adds } const cart = ["Milk"] addItem(cart, "Bread") const bigger = withItem(cart, "Eggs") console.log(cart, bigger)
cart
Bread

Eggs
console
[ 'Milk', 'Bread' ] [ 'Milk', 'Bread', 'Eggs' ]

Prefer returning new values. A function that is not pure is fine when you mean it (printing is one) — just know when you do it.

Three ways to write a function

function double(n) { return n * 2 } // 1 declaration const doubleExpression = function (n) { return n * 2 } // 2 expression const doubleArrow = (n) => n * 2 // 3 arrow console.log(double(21), doubleExpression(21), doubleArrow(21)) // 42 42 42

A declaration is hoisted: you may call it above the line that defines it. A function stored in a const (a function expression — a function used as a value) exists only after that line has run.

The built-in array methods work exactly like this: they loop for you and call your function on each element (find, some and every stop as soon as they have an answer).

Methods that take a callback

forEach
Run a function for each element. Returns undefined.
map
Transform every element → new array, same length.
filter
Keep the elements where the test returns true.
find
The first element that matches, or undefined.
some
true if at least one element matches.
every
true if all elements match.
findIndex
The index of the first match, or -1.
reduce
Combine everything into one value.

Every one of them takes a function. Your function is called once per element, one at a time. (reduce also hands it the running result first — next slide.)

Takeaways

  • 01A function takes parameters, does its work and returns a value — no return means undefined.
  • 02Variables live where they are declared: global, or local to a function or block. Inner wins.
  • 03Arrow functions are a shorter syntax — perfect for callbacks. Defaults cover missing arguments.
  • 04Functions are values: map, filter, find and reduce all take one and call it on the elements for you.
  • 05Prefer pure functions that return new values; recursion always needs a base case first.
